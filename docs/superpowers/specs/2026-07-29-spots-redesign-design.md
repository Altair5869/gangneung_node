# 스팟 페이지(목록+상세) 리디자인 설계 (2026-07-29)

## 배경 및 목적

홈페이지 리디자인(같은 날짜, `2026-07-29-homepage-redesign-design.md`)에서 만든 컬러 토큰·다크모드·타이포 시스템을 우선순위 2순위 페이지인 `/spots`(워크스팟 목록)와 `/spots/[id]`(상세)에 적용한다. 기획서 MVP 1순위 기능이자 홈페이지 CTA("워크스팟 둘러보기")의 도착지라 우선순위가 가장 높다.

홈페이지와 달리 이 페이지들은 **신호등 상태 색상 체계**(조용함/시끄러움, 콘센트 충분함/제한적/없음, 혼잡도 낮음/보통/높음 등)를 카드마다 여러 개 스캔해야 하는 목록형 UI라, 홈페이지처럼 브랜드 컬러(틸/테라코타) 하나로 단순화할 수 없다. 이번 라운드는 새 신호등 토큰 3종을 추가하는 것이 핵심 작업이다.

## 범위

**포함:**
- `app/spots/page.tsx` — 헤더 배너 리스킨
- `components/spots/SpotsClient.tsx` — 필터 바, 그리드 배경 리스킨 (다크모드 포함)
- `components/spots/SpotCard.tsx` — 카드 리스킨 (카테고리 그라디언트 톤 변경, 배지 색상 신규 토큰 적용)
- `app/spots/[id]/page.tsx` — 상세 페이지 리스킨 (히어로, 스펙 카드, 무장애 섹션, 지도 placeholder)
- `components/spots/WorkEnvScore.tsx` — 점수 카드 리스킨
- `app/globals.css`에 신호등 상태 토큰 3종(`--color-good`/`--color-warn`/`--color-bad`) 라이트+다크 추가
- 다크모드 스타일링을 이 페이지 전체(목록+상세+공용 컴포넌트)로 확장 — 홈페이지 라운드에서 "다른 페이지는 다음 라운드"로 미뤄뒀던 부분을 여기서 처음 채움

**제외:**
- `components/spots/SpotFilter.tsx` — 아무 곳에서도 import되지 않는 죽은 코드(90줄). 이번 라운드에서 발견했으나 처리는 별도 결정 사항으로 남김(코드 안 건드림)
- 지도 placeholder를 실제 지도로 교체하는 것 — 색 톤만 바꾸고 기능은 그대로("지도 준비 중" 문구·플레이스홀더 유지)
- `/food`, `/stay`, `/events` 등 다른 페이지 — 후속 라운드

## 디자인 시스템 확장

### 신규 컬러 토큰 — 신호등 상태 색상

`app/globals.css`의 기존 `:root`/`:root.dark`/`@theme inline` 블록에 3개 토큰을 추가한다 (기존 `--color-primary`/`--color-accent` 등과 동일한 패턴).

| 토큰 | 라이트 | 다크 | 의미 |
|---|---|---|---|
| `--color-good` | `#3D7A52` | `#5FBF7E` | 긍정 신호 — 조용함 언급, 콘센트 충분함, 무장애, 혼잡도 낮음, WiFi 있음, 작업환경 점수 최적(80+) |
| `--color-warn` | `#B8862E` | `#D9A648` | 중간 신호 — 콘센트 제한적, 혼잡도 보통, 작업환경 점수 보통(40~59) |
| `--color-bad` | `#B84A3E` | `#E27367` | 부정 신호 — 시끄러움 언급, 콘센트 없음, 혼잡도 높음, 작업환경 점수 낮음(<40) |

미확인(`null`) 상태는 새 토큰을 만들지 않고 기존 `--color-muted`(배경)와 `text-foreground/60`(텍스트, 홈페이지 라운드에서 이미 대비 검증됨)를 그대로 재사용한다 — "모르면 중립색"이라는 기존 관례 유지.

작업환경 점수 4단계(`WorkEnvScore.tsx`의 최적/좋음/보통/낮음)는 3개 신호등 토큰 + 기존 `--color-primary`로 매핑한다: 최적=`good`, 좋음=`primary`(브랜드 틸, "나쁘지 않지만 최고는 아님"이라는 중간 긍정 포지션), 보통=`warn`, 낮음=`bad`.

### 카테고리 톤 변형 (신규 토큰 없음)

`SpotCard.tsx`/`app/spots/[id]/page.tsx`의 `categoryGradient` 맵(현재 카페=주황, 코워킹=파랑, 도서관=에메랄드, 호텔=하늘색, 기타=회색, 5개 서로 무관한 색 계열)을 기존 브랜드 토큰의 그라디언트 조합으로 교체한다. 카테고리는 카드 위 텍스트 배지로 이미 중복 표시되므로 색만으로 구분할 필요가 없다 — 신호등 색상만큼의 색 다양성이 불필요하다는 것이 설계 결정 근거.

| 카테고리 | 그라디언트 |
|---|---|
| 카페 | `--color-accent` 계열 (테라코타) |
| 코워킹 | `--color-primary` 계열 (틸) |
| 도서관 | `--color-primary-dark` 계열 (짙은 틸) |
| 호텔 | `--color-hero-glow` 계열 (밝은 틸 — 다크모드에서 `primary`와 자연스럽게 갈라짐) |
| 기타 | `--color-muted`/`--color-border` 계열 (중립 샌드) |

## 구조 변경

- `SpotsClient.tsx`의 그리드 배경 흐릿한 원형 블롭 장식(`bg-sky-100/60`, `bg-teal-100/50`, `blur-3xl`) 제거 → `bg-background` 단순 배경으로 교체. 홈페이지 라운드에서 이미 블롭 장식을 라인아트로 정리한 흐름과 통일하되, 이 페이지는 카드 그리드가 화면 대부분을 차지해 장식 요소 자체가 불필요 판단 — `HorizonDivider` 재사용 없이 그냥 제거.
- `app/spots/[id]/page.tsx`의 "지도 준비 중" placeholder(현재 `from-sky-50 to-teal-50`, `text-sky-400` 하드코딩)는 기능·문구 변경 없이 색만 `bg-muted`/`border-border`/`text-foreground/60`로 리톤.
- 필터 바(`SpotsClient.tsx`)의 활성 상태 색상(`bg-gray-900`, `bg-blue-600`, `bg-teal-600`, `bg-green-600` — 카테고리/WiFi/무장애/점수 필터가 각각 다른 하드코딩 색을 씀)을 토큰으로 통일: 카테고리·소음·콘센트 필터는 `bg-foreground`(현재 `bg-gray-900`와 동일한 역할), WiFi 토글은 `bg-primary`, 무장애 토글은 `bg-accent`, 점수 필터는 `bg-good`.

## 다크모드 확장

홈페이지 라운드에서는 다크모드 *스타일링*을 홈페이지 한 파일에만 적용하고 나머지 페이지는 토글만 노출한 채 방치했다(의도된 스코프). 이번 라운드는 그 갭을 `/spots` 관련 5개 파일에서 처음으로 메운다 — 별도 인프라 작업 없음(토큰·토글·FOUC 스크립트는 이미 전역에 존재), 각 파일의 하드코딩 Tailwind 색상(`text-gray-900`, `bg-white`, `border-gray-200` 등)을 토큰 클래스(`text-foreground`, `bg-background`, `border-border`)로 교체하고 신호등 배지는 새 `good`/`warn`/`bad` 토큰을 쓰는 것으로 자동으로 다크모드가 적용된다(CSS 변수 스왑 방식이라 `dark:` variant 불필요, 홈페이지와 동일한 메커니즘).

## 테스트 / 검증 계획

- `npx tsc --noEmit`, `npx eslint` 대상 파일
- `npm run build`
- 로컬 `next dev`로 목록·상세 페이지 라이트/다크 각각 렌더 확인
- 신호등 토큰(`good`/`warn`/`bad`) 라이트/다크 각각 WCAG AA 대비 계산 (텍스트/배지 조합)
- 필터 인터랙션 회귀 확인: 카테고리/소음/콘센트/WiFi/무장애/점수 필터 클릭 시 정상 필터링 동작(색만 바뀌고 로직 변경 없음이므로 회귀 위험 낮음)
- 카드→상세 페이지 라우팅 확인
