# 홈페이지 리디자인 설계 (2026-07-29)

## 배경 및 목적

`app/page.tsx` 홈페이지가 전형적인 SaaS 블루/틸 그라디언트 톤이라 "강릉"이라는 지역 고유성이 드러나지 않는다. 관광공사 OpenAPI 공모전 제출작이라는 맥락에서, 기획서(`Gangneung_Node_Plan.md`) 5항목이 명시한 "강릉을 디지털 노마드 거점 도시로 브랜드화"라는 목표를 시각적으로 뒷받침할 필요가 있다.

이번 라운드는 **홈페이지(`app/page.tsx`)만** 리디자인한다. 다른 페이지(스팟/맵/플래너/AI큐레이터/푸드/스테이/이벤트)는 범위 밖이며, 후속 라운드에서 동일 디자인 시스템을 확장 적용한다.

## 범위

**포함:**
- `app/page.tsx` 전체 섹션 리스킨 (컬러/타이포/일러스트) + 레이아웃 재배치
- `app/globals.css`에 디자인 토큰(라이트+다크) 정의
- `NavMenu.tsx`에 다크모드 토글 버튼 추가 (전역 인프라)
- 데이터 규칙 위반 카피 수정: `FeatureCard`(스팟 항목) 설명문의 "WiFi 속도" 문구 제거

**제외 (후속 라운드):**
- 홈페이지 외 페이지(스팟/맵/플래너/AI큐레이터/푸드/스테이/이벤트)의 다크모드 스타일링 및 리스킨 — 토글 인프라는 전역이라 다른 페이지에도 노출되지만, 이번 라운드에서는 다크 전환 시 홈페이지만 새 톤이 적용되고 나머지 페이지는 기존 라이트 스타일 그대로 유지된다(깨지지는 않으나 톤 불일치 존재, 의도된 트레이드오프).

## 디자인 시스템

### 컬러 토큰

`ui-ux-pro-max` 스킬의 컬러 DB(Real Estate/Property "트러스트 틸" 팀, Bakery/Cafe "웜 브라운" 팀)를 참고해 "동해 바다 + 스페셜티 커피" 컨셉으로 커스텀 조합했다. 관광공사 API 활용 서비스라는 신뢰성과, 실사진 없이 일러스트/컬러로 지역색을 내야 하는 제약을 함께 반영했다.

| 토큰 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `--color-primary` | `#0F6B62` | `#35C9B8` | 브랜드 메인, 버튼, 강조 텍스트 |
| `--color-primary-dark` | `#0A3B37` | `#0A3B37` (공용) | 히어로 배경 그라디언트 — 라이트/다크 모드 구분 없이 동일 |
| `--color-accent` | `#B8511E` | `#E2793C` | CTA 포인트, 배지, 하이라이트 |
| `--color-background` | `#FDFAF4` | `#14201F` | 기본 배경 |
| `--color-foreground` | `#241F19` | `#F3EEE3` | 본문 텍스트 |
| `--color-muted` | `#F2EAD9` | `#1C2B29` | 카드/섹션 배경 |
| `--color-border` | `#E6DCC6` | `#2C3E3B` | 카드 테두리 |

히어로 섹션은 이미 짙은 톤(`--color-primary-dark`)을 배경으로 쓰므로 라이트/다크 모드에서 별도 분기 없이 동일한 값을 사용한다.

### 타이포그래피

**Pretendard Variable** 단일 패밀리를 사용한다. 헤딩은 700~800 굵기, 본문은 400~500 굵기로 위계를 표현한다.

`ui-ux-pro-max`가 제안한 라틴 전용 세리프 페어링(Playfair Display, Newsreader 등)은 한글 글리프가 없어 이 사이트처럼 카피 대부분이 한글인 경우 브라우저가 시스템 폰트로 폴백해 의도한 타이포 효과가 사실상 사라진다. Pretendard는 한글/영문/숫자를 모두 고품질로 커버하는 국내 서비스 표준급 웹폰트라 이 문제가 없다. 숫자·영문 라벨(통계 수치, "AI", API 등)은 자간과 굵기로 포인트를 준다.

`globals.css`의 `font-family: Arial, Helvetica, sans-serif;` 하드코딩(기존 버그 — Geist 폰트 변수가 정의돼 있는데 실제로는 미적용)도 이번에 Pretendard로 교체하며 함께 해소한다.

### 일러스트 모티프

실사진 자산이 없으므로, 반복 등장하는 시그니처 라인아트 하나로 지역색을 낸다: **산맥+수평선 실루엣** (대관령 능선 + 동해 수평선을 형상화한 1px 라인 SVG). 히어로 하단 경계선, 섹션 구분선, "왜 강릉인가" 배경에 반복 사용한다. 기존의 흐릿한 원형 그라디언트 블롭(`blur-3xl` 원형 div 2개)을 이 라인 실루엣으로 교체한다.

부차적으로 커피컵 스팀 라인 아이콘을 "이걸 가능하게 하는 것" 섹션의 배지 정도로 소소하게 사용한다. 전부 인라인 SVG로 구현하며 외부 이미지 자산에 의존하지 않는다.

### 다크모드

수동 토글 버튼 방식(시스템 설정 자동 감지가 아님). `NavMenu.tsx`(전역 공용 컴포넌트)에 해/달 아이콘 토글 버튼을 추가한다 — 데스크탑 nav 끝, 모바일 드롭다운 상단.

**상태 관리 및 영속성:**
- `localStorage`의 `theme` 키(`"light"` | `"dark"`)에 저장
- Tailwind v4는 CSS 기반 설정이므로, `globals.css`에 `@custom-variant dark (&:where(.dark, .dark *));`를 선언해 클래스 기반 다크모드 전략으로 전환한다 (기존 `@media (prefers-color-scheme: dark)` 미디어쿼리 전략에서 변경)
- FOUC(첫 페인트 시 잘못된 테마 깜빡임) 방지를 위해 루트 레이아웃(`app/layout.tsx`)에 `<head>` 인라인 스크립트를 추가해, React 하이드레이션 이전에 `localStorage` 값을 읽어 `<html>` 요소에 `dark` 클래스를 동기적으로 적용한다
- 저장된 값이 없으면 라이트 모드를 기본값으로 한다 (시스템 설정 감지하지 않음 — 수동 토글 방식이므로 명시적 선택 전까지는 고정 기본값)

## 레이아웃 재배치

기존 홈페이지는 "강릉에서의 하루"(5스텝 시간 흐름: 일하기/먹기/즐기기/축제/자기)와 "기능 소개"(7개 카드: 워크스팟/AI큐레이터/데이터신뢰성/숙박/맛집/행사/플래너) 두 섹션이 거의 동일한 링크 세트를 중복 나열한다. 성격이 다른 두 종류(장소/목적지 vs. 도구/신뢰 요소)가 섞여 있는 것이 근본 원인이다.

**새 구조:**

1. **히어로** — 기존 유지, 컬러/일러스트만 교체
2. **통계 배너** — 기존 유지, 컬러 리스킨
3. **"강릉에서의 하루"** — 시간 흐름 5스텝(일하기→먹기→즐기기→축제→자기) 유지, 각 카드 설명문은 기존 기능카드의 상세 설명을 흡수해 정보량은 유지
4. **"이걸 가능하게 하는 것"** (신규 분리 섹션) — AI 큐레이터 / 데이터 신뢰성(전화·방문 실측) / 플래너, 3개 카드. "장소"가 아니라 서비스 차별점이므로 별도 섹션으로 분리
5. **"왜 강릉인가"** — 기존 유지, 일러스트 모티프 배경 추가
6. **하단 CTA** — 기존 유지, 컬러 리스킨
7. **푸터** — 기존 유지, 컬러 리스킨

카드 개수는 5+3=8개로 기존 7개(중복 포함 시 12개)보다 스캔 부담이 줄어들며, 실제 정보량(설명 문구)은 손실 없이 재배치만 이루어진다.

## 데이터 규칙 위반 수정

`FeatureCard`(워크스팟 항목) 설명문 "소음도, WiFi 속도, 콘센트 여부로 필터링해 딱 맞는 장소를 빠르게 찾아보세요."에서 "WiFi 속도"를 제거한다. `CLAUDE.md` 데이터 규칙 2에 따라 `wifi.speedMbps`는 수집하지 않는 필드이며(항상 `null`), 이미 이 값 기반 배점도 죽은 배점으로 판단해 제거된 바 있다(`f1ec214` 커밋, `docs/DATA_STATUS.md` 참고). 수정 후 문구는 "소음도, 콘센트 여부로 필터링해 딱 맞는 장소를 빠르게 찾아보세요."

## 에러 처리 / 엣지 케이스

- **FOUC**: 위 다크모드 섹션 참고 — 인라인 스크립트로 하이드레이션 전 처리
- **`localStorage` 접근 불가 환경** (프라이버시 모드 등): `try/catch`로 감싸 실패 시 라이트 모드로 조용히 폴백, 토글 버튼 자체는 세션 내 상태로는 정상 동작
- **다크모드 대비(contrast)**: 위 컬러 토큰 표의 다크 값은 텍스트/배경 조합이 WCAG AA(4.5:1) 이상이 되도록 선정 — 구현 후 실측 검증 필요(아래 QA 항목)

## 테스트 / 검증 계획

- `npx tsc --noEmit` 통과
- 로컬 `next dev`로 홈페이지 실제 렌더 확인 (라이트/다크 각각)
- 다크모드 토글: 클릭 시 즉시 전환, 새로고침 후 선택값 유지(`localStorage`) 확인
- 반응형 확인: 375px(모바일)/768px(태블릿)/1024px+/1440px
- 라이트/다크 각 모드에서 텍스트-배경 대비 WCAG AA 육안 확인 (필요시 대비 계산)
- `grep`으로 "WiFi 속도" 문구 잔존 여부 확인
- 회귀 확인: 홈페이지의 기존 링크(각 섹션 CTA)가 모두 정상 라우팅되는지 확인
